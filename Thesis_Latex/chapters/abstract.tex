\chapter*{Abstract}

Modern automotive software exceeds 100 million lines of code per vehicle, making security testing essential under ISO~26262 and UNECE~WP.29. Fuzz testing effectively discovers vulnerabilities, but writing fuzz drivers requires deep API knowledge that many teams lack. This thesis investigates whether Large Language Models~(LLMs) can automate fuzz driver generation for C/C++ libraries and whether the approach is viable for enterprise CI/CD pipelines.

We evaluated 14~LLMs (1.5B--46.7B parameters) on \texttt{yaml-cpp} and additional C++ targets. The results were counterintuitive: larger models did not perform better. General-purpose models such as Yi~(34B) produced non-functional drivers, and Mixtral~(46.7B) could not be evaluated due to hardware constraints. In contrast, Gemma~3~(27B) achieved 45.06\% line coverage and Qwen~2.5-Coder~(32B) reached 43.08\%. Several code-specialized models including CodeLlama~(34B) also failed, showing that neither size nor specialization label alone predicts success.

Fine-tuning a compact 1.5B model with Low-Rank Adaptation~(LoRA) on OSS-Fuzz drivers reduced generation time by~33\% and token usage by~55\% while maintaining quality. Enterprise deployment at CARIAD~SE revealed that infrastructure challenges, such as corporate firewalls blocking API calls from isolated CI runners, required architectural solutions (Azure Private Link, self-hosted runners). An economic analysis estimates annual deployment cost at approximately~\euro{}1,500.

Overall, LLM-based fuzz driver generation is technically viable and cost-effective for automotive security when models are chosen carefully and infrastructure is adapted to enterprise constraints.
